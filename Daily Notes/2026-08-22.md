# 2026-08-22 - FIX: hidratación muerta en prod por CSP sin nonce

## Que se hizo
- [bug] **Reporte del usuario**: la página de prod no funcionaba; consola Chrome mostraba `Executing inline script violates ... script-src 'self' 'strict-dynamic' 'nonce-...' 'unsafe-inline'`.
- [debug] **Investigación sistemática (causa raíz antes que fix)**:
  - curl a prod `/login`: header CSP exigía nonce pero el HTML tenía **0** apariciones de `nonce=` y ~5 scripts inline sin nonce
  - El middleware (`src/middleware.ts`) ponía el nonce SOLO en headers de respuesta; Next.js necesita la CSP/nonce también en los headers de **request** (`NextResponse.next({ request: { headers } })`) para estampar el nonce en sus bootstrap scripts (patrón oficial de la doc)
  - El layout raíz nunca leía el nonce ni forzaba render dinámico → `/login` servida estática/cacheada
  - **Bug latente desde 2026-07-28** (`4864e85`, CSP hardening): en dev la CSP usa `'unsafe-inline'` sin nonce → nunca se vio; las verificaciones previas de prod fueron HTTP/API-level, nadie ejercitó hidratación en el navegador
- [fix] **Commit `58e8e3b`** — 3 archivos:
  - `src/middleware.ts`: genera nonce, arma `requestHeaders` con `x-nonce` + `content-security-policy`, se los pasa a `updateSession`; sigue seteando ambos headers en la respuesta
  - `src/lib/supabase/middleware.ts`: `updateSession(request, requestHeaders?)` usa `NextResponse.next({ request: { headers: requestHeaders ?? request.headers } })`
  - `src/app/layout.tsx`: `headers().get("x-nonce")` → fuerza render dinámico en todas las rutas (evita que Vercel sirva HTML cacheado con nonce viejo)
- [verify] **RED→GREEN local**: build prod antes del fix reprodujo el bug exacto (8 scripts inline, 0 nonce); después del fix: **28 nonces en HTML, match header==HTML True**
- [verify] **Suite completa**: tsc 0 | lint 0 errores (solo warnings pre-existentes) | **391/391 tests** | build OK
- [deploy] Push `7ca6767..58e8e3b` → deploy Vercel automático → **prod verificado con curl**: 27 nonces en HTML, match con header True. **E2E usuario confirmado: "ya funciona"**

## Decisiones
- Se mantuvo el modelo nonce + strict-dynamic (patrón oficial Next.js) en vez de migrar a hash-based CSP
- Render dinámico global vía consumo de `headers()` en el layout raíz: necesario porque un nonce por-request es incompatible con HTML cacheado (Vercel edge cache tenía HITs de /login)

## Archivos modificados
- `src/middleware.ts` — reenvío de x-nonce + CSP en request headers
- `src/lib/supabase/middleware.ts` — firma nueva de updateSession con headers opcionales
- `src/app/layout.tsx` — lectura de nonce (render dinámico)
